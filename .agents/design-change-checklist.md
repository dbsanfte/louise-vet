# Design change checklist

Use this alongside [AGENTS.md](../AGENTS.md) when editing the
[master game design](../docs/game-design.md). Incorporate answers into the relevant
existing sections; do not create a separate specification for each change.
Omit questions that do not apply.

- **Purpose:** What will the player do, learn, or enjoy? Which pillar and stage
  of the game loop does this serve?
- **Scope/status:** Which feature ID changes? Is it implemented, partial,
  approved/planned, or exploratory? What evidence or completion target supports it?
- **Flow:** How does the player enter, act, understand feedback, succeed, retry,
  and leave? Does vaccination still skip diagnosis? Can an unfinished visit stop?
- **Content:** Do the owner story, pet, tool, visible finding, written clue,
  diagnosis choices, care, and aftercare agree?
- **Progress:** What changes coins, satisfaction, stock, upgrades, arrivals, or
  saving? Do abort/reload have explicit outcomes? Are tuning and code consistent?
- **Access/tone:** Can a child read without time pressure? Are primary actions
  visible on phones? Do touch and keyboard/body guides work? Are retries friendly
  and the care fictional?
- **Presentation:** What models, animation, lighting, audio, or UI are needed?
  Are authoring sources, exports, provenance, and licenses maintained? Does the
  software graphics path stay usable?
- **Integration:** Have loop, mechanics, cases, economy, feature status, acceptance
  criteria, and links been reconciled? Does README need an operational update?
  Does a substantial decision need a rationale in the decision history?
- **Evidence:** What meaningful checks passed? What remains incomplete or
  unverified? Can a new contributor distinguish playable features from future
  intentions without reading the conversation?
